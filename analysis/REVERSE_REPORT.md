## 1. Где «настройка региона»

Найдено **3 места**, задействованных в «региональности»:

1. **Региональные коды (список «предпочтительных региональных кодов») — РАНТАЙМ-настройка**,
   НЕ хранится в .binary. Задаётся хост-приложением через COM-интерфейс
   `VTTrafficAnalyzer.dll` → метод интерфейса `SetPreferableRegionalCodes` (и
   `SetPreferableRegionalCodes_old`). Внутри движка: vtable+0x30/+0x34 объекта
   распознавателя; строки в DLL:
   - `[countryid=%d] Preferable regional codes: %c%s`
   - `[countryid=%d] Preferable regional codes: replacement: %s->%s`
   - `WARNING Attempt to apply regional codes string to OCR`
   Т.е. список регионов приходит **из настроек приложения** (Vocord ITM/Traffic), а не из этих файлов.

2. **Форматы номерных знаков (маски) — в `lprconfig_*.binary`** (секция LPFORMATS).
   Формат = длина, маска позиций (`z`/`*`/разделитель `\x1F`), таблица классов глифов с весами.

3. **Строки-коды в заголовке каждой библиотеки** (.binary, оффсет матрицы +8 и +0x408) —
   2-символьные коды, вероятно серии/регионы (см. ниже), семантика уточняется.

## 2. Структура `lprconfig_*.binary` (LPR2)

```
+0x00: 'LPR2\0\0\0\0'
+0x08: DWORD 1                    (версия контейнера)
+0x10: DWORD 3                    (кол-во под-библиотек)
+0x14: DWORD 0
+0x20: BYTE 13, BYTE 7            (версия формата: v13.7; валидация: major==13 && minor==7)
+0x22: BYTE 3                     (кол-во библиотек)
+0x23: 3 × (DWORD lib_id, DWORD lib_ver)  → (5,35), (7,23), (6,23)
дальше: SLD-запись (матрица, 642192 байт), затем:
  -1 + "LPFORMATS" + blob библиотеки 0
  -1 + blob библиотеки 1
  -1 + blob библиотеки 2
  ... (каждая секция заканчивается -1)
```

### Блоб библиотеки
```
[0] DWORD format_count     — число форматов
[1] DWORD X                (5/7/6 — дублирует lib_id)
[2] DWORD Y                (35/23/23 — дублирует lib_ver)
[3] DWORD glyph_count      — число глифов
глиф-лист: entry0 = (wchar,wchar,float_weight) 8 байт; далее (FFFFFFFF, flag, wchar, wchar, float) 16 байт
МАТРИЦА: 0x20215 DWORD = 526420 байт (фичи шрифта), в начале:
    [+0]=X, [+4]=Y,
    [+0x08] UTF-16 строка кодов 1 (10..12 символов = 5..6 кодов по 2 символа)
    [+0x408] UTF-16 строка кодов 2 (14..24 символа = 7..12 кодов по 2 символа)
форматы: format_count × 10608 байт:
    +0x0C = число позиций (7 у BY, 6 у LT/LV), ≤16
    +0x10 = число классов-глифов
    +0x60 = маска 1 (UTF-16): 'zzzzzz\x1Fz' (BY) / 'zzzzzz' (LT/LV)
    +0xA0 = маска 2 (UTF-16): '******\x1F*' (BY) / '******' (LT/LV)
    +0xE0..: веса позиций (float)
    +0x1D34: таблица классов глифов: (wchar,wchar,weight) + 16-байтные записи (FF,flag,wchar,wchar,weight)
    +0x2134/+0x2138: ссылки на блоки шаблонов (сдвиг 15 бит → в слоте)
FONT-секция: [06][00][0E][14]... (шаблоны глифов 14×20)
```

### Содержимое (по факту)

| Библиотека | id/ver | Алфавит | Глифов | Форматов | Маска формата | Строки кодов |
|---|---|---|---|---|---|---|
| 0 | 5/35 | кириллица-«похожки»: 0-9, **А В С Е Н I К М О Р Т Х** | 22 | **2** | `zzzzzz\x1Fz` (7 поз.) | `8365XKAKOC`, `KMOCBEAKMKHKKH` |
| 1 | 7/23 | латиница: 0-9, A-Z без Q,X | 34 | 1 | `zzzzzz` (6 поз.) | `8365YKAKOCNV`, `KMOCDCBEAKMKHKKHYTULUCNR` |
| 2 | 6/23 | латиница: 0-9, A-Z без Q,X | 34 | 1 | `zzzzzz` (6 поз.) | `8365YKAKOCNV`, `KMOCDCBEAKMKHKKHYTULUCNR` |

- Библиотека 0 = **Беларусь**: формат 4 цифры + 2 буквы + 1 цифра (7 позиций, разделитель).
  По действующим правилам РБ **регион = последняя цифра** (1..7, **8 — новая серия**, добавлена позже).
- Библиотеки 1/2 = **Литва/Латвия**: 6 позиций.
- Строки кодов при разбиении по 2 символа: `83,65,XK,AK,OC` (5 кодов) и
  `KM,OC,BE,AK,MK,HK,KH` (7 кодов) у BY; `83,65,YK,AK,OC,NV` (6) и
  `KM,OC,DC,BE,AK,MK,HK,KH,YT,UL,UC,NR` (12) у LT/LV. Поле [+0]=число кодов в строке 1,
  [+4]=число кодов в строке 2. Семантика (серии/регионы) — уточняется.

## 3. TrafficAnalizerDll.dll — ключевые интерфейсы

- Класс «TrafficAnalizer», vtable в .rdata @ `0x105D3460`, ~90 виртуальных методов (все — thunks).
- `LoadLibrary%02d` (vtable[5] → FUN_10006380) — загрузка .binary:
  парсер заголовка FUN_10001850 (`BinaryInfo`), контейнер FUN_10096090,
  распаковка библиотеки FUN_10096210 (лимит: ≤128 библиотек, ≤32 форматов на библиотеку, ≤16 позиций).
- `SetPreferableRegionalCodes_old` (FUN_10006950/FUN_100067e0) — приём wide-строки кодов.
- `SetFormatEnabled` / `SetFormatWeight` / `SetLibraryWeight` — вкл/выкл форматы и веса.
- `Set_Mask%02d` (vtable[10]) — внешняя маска.
- Обработка масок (FUN около 0x1009EA00): разделители маски = `|`, ` `, `-`, `\x1F`;
  прочие символы → код класса («%.2d »); валидация `exported(%d) != length(%d) [fmt=%d:%d: %s]`.

## 5. План обратной сборки

.binary правится байт-точно (структура фиксированных размеров: заголовки, 16-байтные записи
глифов, 10608-байтные записи форматов, 0x20215-DWORD матрица). Скрипт-парсер читает/пишет файл,
поэтому: правим поля в парсере → пересобираем → проверяем размеры/офсеты → кладём на место.
DLL правятся патчами байт (Ghidra/(hex-редактор) + пересчёт релокаций не требуется при замене
констант в .text/.rdata того же размера).

## 6. ИТОГОВОЕ ЗАКЛЮЧЕНИЕ ПО ВОПРОСУ «РЕГИОНОВ»

**Подтверждено декомпиляцией:**

1. Список региональных кодов («preferable regional codes») **не хранится** ни в одном из
   трёх файлов. Он передаётся движку на этапе конфигурирования хост-приложением через
   COM-интерфейс (`SetPreferableRegionalCodes` / `SetPreferableRegionalCodes_old`,
   параметры: id канала/страны + wide-строка кодов). В DLL только приём и
   использование этой строки (FUN_10006950, FUN_10067e0 → vtable+0x30/+0x34;
   логи `[countryid=%d] Preferable regional codes: %c%s`, `replacement: %s->%s`).

2. В DLL **нет статических таблиц** кодов регионов (проверены .rdata/.data: 16-бит,
   32-бит, ASCII/UTF-16/разделённые списки — найдены только константы π/e).

3. В `lprconfig_*.binary` нет списка регионов РФ. Файл содержит:
   - алфавиты и шаблоны глифов (BY: `АВСЕНIКМОРТХ`; LT/LV: латиница без Q,X);
   - форматы номеров (маски позиций `z`/`*`/`\x1F`, 7 позиций у BY, 6 у LT/LV);
   - строки 2-символьных кодов в заголовке каждой библиотеки (5+7 у BY, 6+12 у LT/LV),
     назначение которых по статике однозначно не установлено (кандидаты: серии букв /
     региональные коды конкретной страны). Для 100%-го ответа нужна динамика (Wine) — не выполнялась по решению пользователя.

4. Экспорты:
   - `TrafficAnalizerDll.dll`: `CTrafficAnalizerCreator_52::Create` (→ `ITrafficAnalizer`),
     `getBinaryInfo(binary, size, sBinaryInfo*, count*)`;
   - `VTTrafficAnalyzer.dll`: стандартные COM (`DllGetClassObject`, `DllRegisterServer`, …).

**Вывод:** чтобы «добавить новые регионы» (РФ: 777, 977, 750 и т.п.), править эти три файла
не нужно и **нельзя ограничиться ими** — список регионов приходит из настроек приложения
(Vocord ITM/Traffic). Эти файлы нужны лишь если требуется править **форматы номеров**
(раскладку позиций, алфавиты, веса глифов) — механизм и парсер для этого готовы
(`analysis/parse_binary.py`, `analysis/REVERSE_REPORT.md`).
